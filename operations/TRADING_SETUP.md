# Trading setup status — no live order engine

Owner has selected USD $25 total buying budget, USD $10 loss threshold for stopping new buys, and reserving half the bot trading balance when it is strictly above $200. These terms are now part of `trading-readiness.js`; they do not authorize unspecified individual orders, asset liquidation or withdrawals.

This change adds an authenticated readiness check and a Trading setup screen, not an automatic trader. The Start button is explicitly unavailable and POST /api/trading/start returns 409. No order is sent and no live write adapter, position ledger or scheduler is installed. Installing a check must not be presented as completing trading setup.

## Fixed read operations

The existing official CLI runner now has an explicit read-command allowlist. It supports portfolio listing/get, current-key permission inspection, and scoped paginated balances. There is no order, transfer, arbitrary argument, shell or dynamic URL path. Permission inspection validates the returned portfolio UUID; balance pagination validates portfolio on every page, detects non-progress, caps pages, requires completion, and accepts exactly one ready/active USD account. Decimal strings retain precision. Staked assets, futures margin, USDC and aggregate cash equivalents are not substituted for USD. Unknown values stay unknown.

The same key configuration and credential isolation as the original account reader are retained. Read results are cached for 60 seconds and concurrent requests coalesce. Nothing upgrades key permissions. The app does not copy or use the separate ChatGPT plugin's OAuth credentials.

## Known blockers

- The owner created this tracker's key with View only; the readiness endpoint must verify its current permission rather than relying on that history.
- A fresh read through the separate official Coinbase ChatGPT connection on November 21, 2026 (America/Phoenix) returned available USD 0 for the Default portfolio. The app independently checks its own selected portfolio/key; plugin and tracker access are distinct.
- Balance/product visibility does not establish equity eligibility. No financial order is used as an eligibility test.
- Installed pinned official CLI 0.0.11 documents no equity preview support. Its fees/fill/cost estimates cannot be invented. Treat current discovered help as authoritative over older bundled skill examples (some old examples use unsupported equity USDC or autogenerated order IDs).
- Specific entry/exit/per-order plan and tested durable live execution/reconciliation/scheduler remain unimplemented. Do not advise granting broad financial permissions or funding as though those were the only remaining steps.

The $10 stop-new-buys threshold is not an insured loss cap, does not liquidate holdings, and cannot prevent gaps, fees or market losses. Starting an unsupported or empty engine would misrepresent the state; all success paths in this readiness module still report ordersEnabled=false and automaticTrading=false.
